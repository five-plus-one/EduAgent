# 多模态AI互动式教学智能体 - 后端服务规划与接口架构

> 对应前端的沉浸式工作台，后端致力于打造一个高响应、强并发的“AI 业务总线”，负责大模型调度的中枢控制以及密集资料处理。

## 1. 后端技术栈概览

| 类别 | 推荐选型 | 核心优势 |
| --- | --- | --- |
| **基础语言与框架** | **Python 3.10+ & FastAPI** | 提供了卓越的异步支持和 ASGI 性能。最关键的是，它是构建 AI 应用和实现 SSE 流式推流的最佳原生搭档。 |

## 2. 核心架构与业务总线设计 (Backend Logic Core)

不同于传统的 CRUD 增删改查系统，本项目后端采用基于会话 (Session) 和记忆 (Memory) 的“状态机”设计，以适配多轮 AI 对话这种非确定性的流式业务。

### 2.1 高并发流式响应引擎 (SSE Engine)

面向前端要求“像打字机一样极速反馈”的用户体验，后端全面抛弃传统的 Request-Response 停等模型：
- 当接收到 `/chat` 请求后，FastAPI 利用异步生成器 (`yield`) ，将大模型吐出的每一次 Chunk 以 `text/event-stream` 格式持续写入管道。
- 在推流的过程中，后端会并行执行“记忆更新”和“意图提取校验”，确保流完最后一个字时，JSON 结构化课件元数据同时也下发到前端。

### 2.2 RAG 文档处理工作流 (Document Ingestion Pipeline)

应对多模态文件上传，我们设计了旁路异步处理链：
1. **统一上传口**：接收前端传入的 `multipart/form-data` 文件并生成唯一 `file_id`。
2. **多模分发路由**：
   - PDF / Word -> 送入 PyPDF2/python-docx 提取清洗文本 -> 调用 Embeddings API -> 持久化入 Chromadb。
   - 视频/音频 -> 送入转录服务提取带时间戳文本 -> 按关键帧切片入库。
3. **进度轮询池**：供前端实时获取解析进度，展现环形进度条微动效。

### 2.3 生成机制：“智能+确定性”解耦引擎 (Decoupled Generator)

由于直接让大模型输出二进制如 .pptx 文件往往面临幻觉和文件损坏率极高的问题，我们将生成过程**分为“两段式”拦截**：

- **阶段一：大模型结构化提取** —— 结合对话意图与 RAG 知识片段，强制令 `doubao-seed` 大模型返回严格匹配 Pydantic BaseModel 约束的 **JSON Schema**。前端读取此 JSON 渲染出极为平滑的白板界面预览。
- **阶段二：纯逻辑拼建** —— 当教师在前端确认定稿请求导出 (接口 `4.1 /export`)，后端采用 `python-pptx`，以传统物理脚本堆砌的方式，忠实地将 JSON 数据“拼”成物理 PPT 文件并保存到磁盘提供下载 URL，保证 100% 的导出成功率与稳定极速的体验。

## 3. 设计原则

- **极简外挂原则**：坚守目前开发目录的约束，不依赖需要独立部署的外部中间件环境，把一切必要的环境封装在 `requirements.txt` 和项目的私有 DB 内。
- **状态不丢失 (Stateless API vs Stateful Agent)**：API 本身必须是无状态的（方便扩容），但用户的全部对话上下文将由 SQLAlchemy 深度绑定唯一的 `session_id` 持久化管理。
