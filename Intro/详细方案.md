# EduAgent 项目详细解决方案

## 一、项目背景与核心命题

EduAgent 选题源自锐捷网络 2026 年企业命题赛题：**智能计算方向 · 多模态 AI 互动式教学智能体（应用类）**。

### 1.1 整体背景

随着教育信息化 2.0 行动的深入推进，生成式 AI 正成为重塑教学模式的核心驱动力。然而当前 AI 教学辅助工具普遍存在两大顽疾：

- **功能碎片化**：教师需跨越多个互不联通的软件（演示文稿工具、文档编辑工具、图片搜索工具、AI 写作工具等），流程割裂，数据孤岛，重复劳动量大
- **意图理解浅层化**：现有工具只能执行单次、简单的指令，无法与教师进行多轮、深入对话以精准把握其复杂教学思路和个性化要求

### 1.2 命题核心要求

| 要求 | 具体说明 |
|---|---|
| 本地知识库 RAG | 收集专业知识库资料，实现文本处理、向量化、检索 |
| 多模态交互输入 | 语音输入 + 文字输入，支持多轮对话与意图澄清 |
| 参考资料上传 | 支持 PDF、Word、PPT、图片，与教师意图对应匹配 |
| 课件生成引擎 | PPT 演示文稿 + Word 教案文档，图文并茂，逻辑清晰 |
| 迭代优化与导出 | 预览界面、修改意见理解、.pptx + .docx 标准格式下载 |

## 三、核心功能详细实现

### 3.1 用户认证与会话管理

#### 认证体系

系统采用标准 JWT + Refresh Token 双 Token 机制：

- `/auth/register`：创建教师账户（默认主题 `tech_blue`）
- `/auth/login`：提交用户名+密码，返回 `access_token`（2h）+ `refresh_token`
- `/auth/me`：获取当前用户信息及偏好设置（语言、主题、默认 AI 模型）
- `/auth/me/preferences`：部分更新偏好（支持 PATCH 语义，仅传需要修改的字段）
- `/auth/logout`：后端将 token 加入黑名单

前端在 `apiClient` Axios 实例中通过请求拦截器自动注入 Bearer Token，响应拦截器统一处理 401（清除 localStorage 并重定向登录页）。

#### 会话生命周期

每个"备课会话（Session）"是系统的核心数据容器：

```sql
-- SessionContext 表核心字段
session_id      VARCHAR PK   -- 唯一标识
user_id         VARCHAR FK   -- 归属教师
course_name     VARCHAR      -- 课程名称
target_audience VARCHAR      -- 受众（如"大一新生"）
objective       TEXT         -- 教学目标
created_at      DATETIME
updated_at      DATETIME
```

支持完整 CRUD：创建（`POST /sessions`）、列表分页查询（`GET /sessions?page&size&keyword`）、详情获取（`GET /sessions/{id}`，包含 messages + associated_files）、重命名（`PUT /sessions/{id}`）、删除（`DELETE /sessions/{id}`）。

### 3.2 多模态对话交互（Chat + Tool Calling）

#### SSE 对话接口

`POST /sessions/{session_id}/chat`（`Accept: text/event-stream`）是系统最核心的交互接口：

```
请求 → FastAPI 异步生成器
    → 大模型 API（httpx 异步流式）
    → 实时解析 delta chunk
    → yield SSE 事件
```

SSE 事件类型定义：

```typescript
// 深度思考透出
{ event_type: "thinking", chunk: "正在分析教学目标..." }
// 普通文本（打字机效果）
{ event_type: "text", chunk: "好的，我来帮您...", is_finished: false }
// 工具调用通知
{ event_type: "tool_call", tool_call: { tool_name: "UpdateSlide", arguments: {...} } }
// 工具执行完成（触发前端刷新）
{ event_type: "tool_result", tool_result: { tool_name: "UpdateSlide", status: "success", should_refetch_ppt: true } }
// 终止帧
{ event_type: "text", chunk: "", is_finished: true, extracted_intent: null }
```

系统提示词（SYSTEM_PROMPT）关键规则：
1. 严禁在对话通道输出 Markdown 格式课件草稿，课件修改必须通过工具调用执行
2. AddSlide 必须传入完整结构化 `new_elements` 数组，禁止使用 `content` 字符串参数
3. 将某页分成两页时：先 UpdateSlide 修改原页，再 AddSlide 插入新页

#### Tool Calling 流式拼装机制

大模型流式返回 tool_calls 时，delta 中的 `arguments` 字段是分块到达的 JSON 字符串片段。后端维护 `tool_calls_buffer: dict[int, dict]`，按 `index` 分组拼接 `args_str`，流结束后统一解析执行：

```python
# 核心拼装逻辑
for tc in delta.get("tool_calls") or []:
    idx = tc.get("index", 0)
    if idx not in tool_calls_buffer:
        tool_calls_buffer[idx] = {"name": "", "args_str": ""}
    tool_calls_buffer[idx]["args_str"] += tc.get("function", {}).get("arguments", "")
```

执行阶段根据工具名称路由到对应逻辑（UpdateSlide/AddSlide/DeleteSlide），操作 `Courseware.ppt_data` JSON 字段，通过 `flag_modified(cw, "ppt_data")` 触发 SQLAlchemy 变更检测后提交。

#### 语音输入

`POST /sessions/{id}/audio-chat`：前端通过 `MediaRecorder API` 录音，编码为 `audio/webm`，以 `multipart/form-data` 上传，后端调用大模型 ASR 能力将音频转文字后返回。前端确认后将文字投入 Chat 输入框，再走对话流程。

### 3.3 RAG 文档处理管道（详细）

#### 文件接收

`POST /sessions/{id}/files`：
1. 服务器接收 `multipart/form-data` 文件，生成唯一 `file_id`（`f_` + uuid8）
2. 实体存入 `SessionFile` 表（status: `pending`）
3. **立即返回 `{ file_id, status: "processing" }`**（不阻塞请求）
4. 注册 `BackgroundTask` 异步执行向量化

#### 多格式文本提取（document_parser.py）

```python
def extract_text_from_file(file_path, filename):
    ext = os.path.splitext(filename)[1].lower()
    if ext == ".pdf":    return parse_pdf(file_path)     # pypdf 逐页提取
    elif ext in (".docx", ".doc"): return parse_docx(file_path)  # python-docx 段落提取
    elif ext == ".pptx": return parse_pptx(file_path)    # python-pptx 幻灯片文本提取
    elif ext in (".txt", ".md", ".json", ".csv"):
        return parse_txt(file_path)  # 多编码自适应（UTF-8/GBK/Latin-1）
    else:
        raise ValueError(f"不支持的文件格式：{ext}")
```

#### 分块向量化入库（vector_store.py）

```python
def store_document_vectors(text, document_id, metadata=None):
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=1000,    # 每块约 500-1000 个中文字符
        chunk_overlap=150   # 150 字重叠，保留上下文连贯性
    )
    docs = splitter.create_documents([text], metadatas=[metadata or {}])
    for d in docs:
        d.metadata["document_id"] = document_id  # 注入 document_id 用于后续按文件过滤
    get_vector_store().add_documents(docs)
```

ChromaDB 使用 `PersistentClient`，数据持久化在 `chroma_db/` 目录（跨进程重启不丢失）。

#### RAG 增强生成

生成课件时，取最后一条对话消息作为 query，对 `selected_file_ids`（前端选中的参考文件）做过滤检索：

```python
results = vector_store.similarity_search(
    query=last_message,
    k=6,
    filter={"document_id": {"$in": selected_file_ids}}
)
rag_context = "\n---\n".join([doc.page_content for doc in results])
```

检索结果以"【RAG参考材料】"格式注入 LLM Prompt，大模型生成内容时显著依赖这些知识片段。

#### 知识库全局管理

`/knowledge-base/documents` 接口允许管理员维护全局知识库（独立于任何具体会话）。`/sessions/{id}/references` 接口支持将全局知识库文档"挂载"到指定会话，而无需重复上传，实现知识资产复用。

### 3.4 流式课件生成引擎（详细）

#### NDJSON 流协议设计

`POST /sessions/{id}/generate/stream` 采用独创的 NDJSON（逐行 JSON）协议，大模型的输出本身被约束为 NDJSON 格式（每行一个完整 JSON 对象），后端在线解析并即时转发 SSE：

大模型输出示例（原始流）：
```json
{"__type": "theme", "name": "科技蓝", "bg_color": "#0F172A", "primary": "#38BDF8", ...}
{"__type": "page", "page_index": 1, "layout_type": "cover", "title": "人工智能导论", ...}
{"__type": "page", "page_index": 2, "layout_type": "minimal_list", ...}
{"__type": "word_start"}
## 第一章 课程导论
详细讲义内容...
{"__type": "done"}
```

#### 流式解析引擎

后端对流式 delta 进行在线 JSON 解析（`json.JSONDecoder.raw_decode`）：

```python
buffer = ""
while True:
    brace_pos = buffer.find('{')
    if brace_pos == -1: break
    buffer = buffer[brace_pos:]  # 跳过前置非 JSON 内容
    try:
        obj, idx = decoder.raw_decode(sanitized_buffer)
        buffer = buffer[idx:]   # 消费已解析的部分
        # 分发处理：theme / page / word_start / done
    except json.JSONDecodeError:
        break  # JSON 不完整，等待更多 chunk
```

LaTeX 转义修复（防止 JSON 解析失败）：
```python
def _escape_fixer(m):
    val = m.group(0)
    if val in ['\\"', '\\\\', '\\n'] or val.startswith('\\u'):
        return val  # 保留合法转义
    return '\\\\' + val[1:]  # 修复 \vec \Delta 等 LaTeX 命令变为 \\vec \\Delta

sanitized_buffer = re.sub(r'\\.', _escape_fixer, buffer)
```

#### 逐页图片向量检索注入

每解析完一个 `page` 对象，立即对其中 `type: "image"` 元素执行向量检索：

```python
for elem in obj.get("elements", []):
    if elem.get("type") == "image":
        query = elem.get("query", "")
        resolved = search_image_by_query(query, session_id)
        elem["resolved"] = resolved  # None 或 {image_id, preview_url, source, similarity}
```

检索结果随页面数据一同推送给前端，前端渲染时直接使用 `resolved.preview_url`。

#### WCAG 对比度守护

主题推送前，后端自动校验背景色与文字颜色的对比度：

```python
def _luma(hex_str):
    r, g, b = int(h[0:2],16), int(h[2:4],16), int(h[4:6],16)

L1, L2 = max(bg_l, txt_l), min(bg_l, txt_l)
if (L1 + 0.05) / (L2 + 0.05) < 3.0:  # 对比度不足时自动补救
```

### 3.5 图片语义检索系统（详细）

#### 两级图库架构

| 属性 | 会话图片库 | 系统默认图库 |
|---|---|---|
| 可见范围 | 仅上传者本次会话 | 所有用户（后台预置）|
| 上传者 | 普通教师 | 仅管理员（`X-Admin-Key` 鉴权）|
| API 前缀 | `/sessions/{id}/images/` | `/admin/image-library/` |
| ChromaDB 集合 | `images_session` | `images_library` |
| 数据库表 | `session_image` | `image_library` |

#### Vision LLM 自动标注

上传图片后，异步执行 Vision LLM 标注（`doubao-vision-pro-32k`）：

1. 读取图片文件 → Base64 编码
2. 构造多模态消息（`image_url` + `text` 组合）
3. 系统 Prompt 要求输出严格 JSON：
   ```
   {"description": "苹果从树上落下的黑白手绘示意图，用于讲解牛顿万有引力定律",
    "tags": ["牛顿", "引力", "苹果树", "物理", "手绘", "经典力学", "示意图"]}
   ```
4. 提取 description + tags → 拼接字符串 → `text-embedding-3-large` 向量化
5. 存入 ChromaDB 对应集合，metadata 记录 `image_id` 与 `session_id`
6. 更新数据库 `annotate_status: done`，前端轮询到状态更新后呈现描述与标签

#### 向量检索策略

```python
def search_image_by_query(query: str, session_id: str) -> Optional[dict]:
    # 1. 优先搜会话图库（高阈值 0.75，精准匹配）
    results = store.similarity_search_with_relevance_scores(
        query, k=1, filter={"session_id": session_id})
    if results and results[0][1] >= 0.75:
        return {"image_id": ..., "source": "session", "similarity": ...}

    # 2. Fallback 到系统图库（宽泛阈值 0.70）
    results = library_store.similarity_search_with_relevance_scores(query, k=1)
    if results and results[0][1] >= 0.70:
        return {"image_id": ..., "source": "library", "similarity": ...}

    return None  # 前端渲染灰色占位框
```

#### 前端图片上传面板（ImageUploadPanel 组件）

- 支持拖拽 / 点击多选上传（jpg/png/webp，单张最大 10MB）
- 缩略图网格展示，标注状态徽章（待标注 / 标注中 / 已就绪 / 失败）
- 标注完成后展示 LLM 生成的描述和标签（可折叠）
- 对 `pending/processing` 状态图片每 3 秒轮询，直到 `done` 或 `failed`
- 失败时显示"重新标注"按钮，调用 `POST /images/{id}/annotate`

### 3.6 PPTX 导出引擎（详细）

`ppt_exporter.py` 是项目技术含量最高的单体模块（2301 行），实现了从 JSON 数据到物理 .pptx 文件的完整转换。

#### LaTeX → OMML 数学公式转换（核心创新）

完整实现递归 LaTeX 解析器，将 PPT 幻灯片中的数学表达式转换为 Office Math Markup Language（OMML）XML 节点，直接嵌入 `.pptx` 文件的 XML 层：

**支持的 LaTeX 结构（`_append_omml_for_expr` 递归函数）**：

```
\frac{num}{den}     → <m:f><m:num>...</m:num><m:den>...</m:den></m:f>
\sqrt[n]{x}         → <m:rad><m:deg>n</m:deg><m:e>x</m:e></m:rad>
\sum_{lo}^{hi}{e}   → <m:nary><m:chr>∑</m:chr>...limits...</m:nary>
\int \prod \oint    → 同上，各自对应 Unicode chr 值
\lim_{x→0}         → <m:limLow><m:e>lim</m:e><m:lim>...</m:lim></m:limLow>
\left( ... \right)  → <m:d><m:dPr><m:begChr>(<m:endChr>)</m:dPr>...</m:d>
^{exp}              → <m:sSup><m:e>base</m:e><m:sup>exp</m:sup></m:sSup>
_{sub}              → <m:sSub><m:e>base</m:e><m:sub>sub</m:sub></m:sSub>
```

**方程组环境（`\begin{cases}...\end{cases}`）**：

```python
def _build_cases_omath(lines: list, color_hex: str) -> etree._Element:
    omath = etree.Element(f'{{{_NS_M}}}oMath')
    d_elem = etree.SubElement(omath, f'{{{_NS_M}}}d')
    # 左大括号 delimiter
    dPr = etree.SubElement(d_elem, f'{{{_NS_M}}}dPr')
    begChr.set(f'{{{_NS_M}}}val', '{')  # 左 {，右为空
    # 方程数组
    eqArr = etree.SubElement(e_outer, f'{{{_NS_M}}}eqArr')
    for line in lines:  # 每行一个 <m:e>，内含完整表达式
        eqArr.append(_latex_line_to_omml(line, color_hex))
```

还支持矩阵类（`pmatrix`(括号)、`bmatrix`(方括号)、`vmatrix`(竖线)）和对齐方程组（`aligned`/`align`）。

**色彩注入**：OMML 内所有数学符号运行（`<m:r>`）均注入 DrawingML 颜色属性，确保数学公式文字颜色继承主题文字配色。

## 四、项目创新点总结

### 4.1 技术创新

| 创新点 | 描述 |
|---|---|
| **Vision RAG 双轨检索** | 文档 RAG（知识增强）+ 图片 Vision RAG（图片自动匹配）并行，构建多模态知识检索体系 |
| **NDJSON 在线流式解析** | 大模型输出被约束为 NDJSON 格式，后端在线解析实现真正的逐页流式生成，而非等全量生成完毕 |
| **LaTeX → OMML 完整转换引擎** | 自研递归 LaTeX 解析器（支持 20+ LaTeX 命令结构），导出的数学公式为真正的 Office Math 对象 |
| **AI + 确定性双轨解耦** | 大模型只输出 JSON，python-pptx 纯逻辑拼装，彻底分离"智能决策"与"确定性执行" |
| **前后端主题强一致性** | 相同 `PREMIUM_THEMES` 字典 + 相同 `simple_hash` 算法，确保预览与导出主题像素级一致 |
| **WCAG 对比度自动守护** | 主题应用时自动校验背景-文字对比度（WCAG 3.0 标准），不达标时自动修复为高对比度组合 |

### 4.2 产品创新

| 创新点 | 描述 |
|---|---|
| **思考过程可视化** | 大模型 `reasoning_content` 实时流式透出，教师可看到 AI 的推理过程，消除"黑盒困惑" |
| **会话即容器** | 对话历史、文件、知识库引用、课件数据、图片库全部聚合于 session_id，实现真正的"备课工作空间" |
